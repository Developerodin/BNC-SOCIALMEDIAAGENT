# M4: Chat API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A storefront can `POST /api/chat` and receive a streamed (SSE) answer grounded only in that store's products. Product cards carry live price, stock, availability and link, and the conversation continues across page loads.

**Scope (phase 1 plan, M4 row):** SSE chat with server-minted tokens, small→large escalation, markers and live cards, masking, D35 limits, and chat history across pages (UD13). It also carries the 2026-11-24 decisions assigned to M4: D71 (link fallback), D72 (sold-out cards), D74 (gift cards only when asked), D75 ("View options"), D76 (translate the query), D77 (market availability), D79 (live data wins), plus the prompt-injection guard (§7.6, §8).

**Out of scope (later milestones):**
- the widget, card rendering and add to cart (M5),
- rate limits, the monthly cap, Turnstile, the spend cap and retention (M10; D40, D9, D41 retention),
- thumbs feedback (M5/M7),
- FAQ and PDF chunks in retrieval (M6/M7).

M4 records token usage per message, so M10 only has to sum it.

**Already done before M4:**
- **D74 sync and search** (commit `42377c3`): `products.is_gift_card` (migration `0007`), sync fetches `isGiftCard`, and `search(storeId, query, k, { includeGiftCards })` excludes gift cards by default.
- **Review fixes** (commits `a33135c`, `503bf2d`): the 2-chunks-per-product cap in search, `stores.sync_error`, the byte-based token estimate, category and extra metafield types, and dashboard counts.

M4 only has to set the gift-card flag from the chat (Task 16) and double-check it live (Task 15).

**Architecture (one turn):**
1. **Request checks.** The route checks the Origin against the store's domains, verifies or mints the conversation token, masks the message (D41), and saves it.
2. **Rewrite** (small model, structured output). It turns the latest message plus recent history into `{ query, includeGiftCards }`, with `query` in the store's language (D76, D74).
3. **Search.** `search(storeId, query, 8, { productId, includeGiftCards })`.
4. **Live check.** One Admin `nodes(ids:)` call for every product in the hits plus the current product (§7.6, D44). Products that can't be sold to this shopper are removed *before* the model sees them.
5. **Answer.** The small model streams. `[[escalate]]` in the first tokens re-asks the large model (D34). Markers are stripped from the text stream and turned into `product` events, built from the live-check data only (D36).
6. **Save and close.** The assistant message is saved with token usage, the model used and a card snapshot, then the server sends `done {conversationToken}`.

**Tech Stack:** as M3 (Next.js 16.4.6, Drizzle, pg-boss 12, `@shopify/shopify-api` 15.1.2 on API `2026-10`, `openai` 7.62, Vitest). No new dependency.

**Spec:** `product.md` §7.6, §7.7 (rendering safety), §7.13 (`Conversation`, `Message`), §8, and D25, D30, D34–D38, D41, D42, D44, D48, D49, D71, D72, D74–D79. `ui-ux.md` UD10, UD12, UD13, UD22. ## Next.js notes (checked in `node_modules/next/dist/docs`, 16.4.6)

- **Route handlers:** `export async function POST(req: Request)` and `OPTIONS`. Next implements `OPTIONS` itself only when the route doesn't define it, so we define it for the CORS preflight (`03-file-conventions/route.md` §CORS).
- **SSE:** return `new Response(readableStream, { headers })` from the handler (`02-guides/streaming.md`, "Streaming in Route Handlers"). Headers:
  - `Content-Type: text/event-stream; charset=utf-8`
  - `Cache-Control: no-cache, no-transform`
  - `X-Accel-Buffering: no`
- **Buffering:** reverse proxies and gzip/brotli can hold a stream back (`streaming.md`, "Reverse proxies" and "Compression").
  - **Task 19 step:** check whether `next start`'s built-in compression buffers `text/event-stream`. If it does, turn compression off for this route, or set `compress: false` and let Caddy compress the other routes.
  - **M10 note:** Caddy's `reverse_proxy` needs `flush_interval -1` for this path.
- **`after()`** (`04-functions/after.md`) works in route handlers. Use it for logging after the response only, never for saving the answer; the stream's own end does that.
- **Client disconnects** aren't covered by the docs. **Task 19 step:** confirm on the dev server that the stream's `cancel()` callback and/or `req.signal` fires when the client aborts, and use whichever fires.
- **CORS lives in the route.** `src/proxy.ts`'s matcher skips `/api`, so the proxy never sees chat requests.

## The one `nodes(ids:)` call (Task 15)

```graphql
query LiveProducts($ids: [ID!]!, $ctx: ContextualPublicationContext!, $withCtx: Boolean!) {
  nodes(ids: $ids) {
    ... on Product {
      id status publishedAt isGiftCard requiresSellingPlan tracksInventory hasOnlyDefaultVariant onlineStoreUrl
      featuredMedia { preview { image { url } } }
      options { name values }
      publishedInContext(context: $ctx) @include(if: $withCtx)
      variants(first: VARIANT_CAP) {
        pageInfo { hasNextPage }
        nodes {
          id availableForSale inventoryQuantity inventoryPolicy inventoryItem { tracked }
          price compareAtPrice selectedOptions { name value }
        }
      }
    }
  }
}
```

`VARIANT_CAP` is set by **C12**. `onlineStoreUrl` is fetched because it's in §7.6's list, but it's only logged, never used.

**Which products are kept** (§7.6, verified 2026-11-24):
- `status = ACTIVE`, and `publishedAt` is set and not in the future,
- with a country, `publishedInContext = true` (D77),
- `isGiftCard` products only when the turn asked for gift cards (D74).

**Stock per variant:**
- `availableForSale = false` → sold out,
- `inventoryItem.tracked` and `inventoryPolicy = DENY` → `{ kind: "count", n: inventoryQuantity }`,
- anything else → `{ kind: "in_stock" }`,
- never `totalInventory`.

**Other card fields:**
- the product is `available` when any variant is,
- `imageUrl` is kept only when its host is `cdn.shopify.com`,
- the price is the variant's `price` (the store's default market, in `stores.currency_code`), and `compareAtPrice` is passed through.

## Global Constraints (M4 additions)

- **New tables are store-owned.** `conversations` and `messages` get a `store_id` column, ENABLE + FORCE RLS, the `store_isolation` policy, and `ON DELETE CASCADE` from `stores`. The RLS coverage test enforces this.
- **No prices in the text.** The model never states prices in its answer (D37). Prices appear only in `product` events.
- **Only checked product IDs.** Every `[[product:id]]` must be in this turn's live-checked set: the search hits plus the current product. Unknown IDs are dropped silently (D36).
- **Mask first.** Shopper text is masked (D41) **before** it is stored, rewritten, embedded or sent to OpenAI. History is read back already masked.
- **D35 limits.** Input up to 2,000 characters (413 beyond that), history = the last 20 messages, `max_output_tokens: 1000`.
- **OpenAI settings.** Calls use `store: false` (D34). Model names come from `OPENAI_MODEL_SMALL` and `OPENAI_MODEL_LARGE`, which are added to `.env.example`.
- **No outside calls in a transaction.** No OpenAI or Shopify call runs inside a DB transaction (the same rule as M3).
- **Token secret.** `CHAT_TOKEN_SECRET` (32 random bytes, base64) is added to `.env.example`. Tokens and message bodies are never logged (§7.10).
- **Default test run stays offline.** Nothing in `npx vitest run` calls OpenAI or Shopify. Live tests use `test.skipIf(!process.env.OPENAI_API_KEY)`, as in M3.
- **D49 items.** Prompt wording, card fields and notice text are drafted here by Claude and approved by the user before the beta.

## Review Focus

1. **A marker that names another store's product, a product not in this turn's hits, or a dropped product** (draft, unpublished, other market, gift card) never becomes a card. Tests in Tasks 18 and 19.
2. **A conversation token from store B, or a tampered token, used with store A's `shop`** is rejected and never reveals B's history. Tests in Tasks 14, 19 and 20.
3. **A request from an Origin not in the store's domains, or with no Origin,** is refused before any OpenAI or Shopify call. Test in Task 19.
4. **An email or phone number in the message** is masked in the stored row, the rewrite input, the embedded query and the answer prompt. Tests in Tasks 14 and 19.
5. **The small model starts with `[[escalate]]`:** no small-model text reaches the client, and the large model answers. A marker split across deltas is still parsed. Test in Task 18.
6. **A product description that says "only $9 today, 2 left", or contains `[[product:…]]` or `[[escalate]]`,** can't inject markers, and the prompt carries the D79 rule. Tests in Tasks 17 and 21.
7. **The shopper disconnects mid-answer:** the OpenAI request is aborted and the process doesn't throw. Test in Task 19.
8. **Shopify is throttled, the token has expired, or the `nodes` call fails:** the turn still answers per C11 and never shows an unchecked price or stock. Tests in Tasks 15 and 19.

**Files:**
- Create: `src/lib/chat/markers.ts`, `src/lib/chat/answer.ts`

**Interfaces:**
- Produces:
  - **`createMarkerParser(allowed: Map<string, string /* n → GID */>)`** with `push(delta) → { text: string; products: string[] }` and `end()`.
    - It holds back a trailing partial `[[…` (up to 40 characters) until it can tell what it is.
    - It strips every `[[…]]` from the text.
    - It emits each GID once per answer, and only when `n` is in `allowed`.

  - **`answer({ system, input, signal, onText, onProduct })`** returns `Promise<{ model: "small" | "large"; text; status: "ok" | "cut_off"; tokens }>`.

    - **Logging.** Each escalation is logged per store (`console.info("chat escalated", { storeId })`); M10 turns that into a metric.
    - **Timeouts per C13.** Until C13 is decided, build the timer with two configurable values, first-token and total, both defaulting to 20 s to match §8's "20 s".
    - **OpenAI 429 or 5xx before the first token.** One retry after 1 s if the time budget allows, then throw `ChatUnavailable`.
    - **The same errors after the first token.** No retry; stop with `status: "cut_off"`.
    - **Shopper disconnects.** When `signal` is aborted, it aborts the OpenAI request and returns `cut_off`.

### Task 19: `POST /api/chat` (SSE)

**Files:**
- Create: `src/app/api/chat/route.ts`, `src/lib/chat/cors.ts`, `src/lib/chat/turn.ts`, `src/lib/chat/sse.ts`

**Interfaces:**
- **Request:** `POST` with JSON `{ shop, conversationToken?, message, productId?, country?, pageUrl? }`. `country` is added for D77: an ISO 3166 alpha-2 code, validated.
- **`corsFor(req, store)`:**
  - `Origin` must equal `https://<host>` for a host in `stores.domains` (Task 13),
  - no Origin → 403,
  - otherwise the response echoes the Origin, with `Vary: Origin`,
  - `OPTIONS` answers the preflight for `POST` with `Content-Type`.
- **Order of work.** Each check runs before any OpenAI or Shopify call where possible.
  1. Validate `shop` against `^[a-z0-9-]+\.myshopify\.com$` and load the store. Unknown or inactive → 404.
  2. CORS → 403.
  3. An empty `message` → 400; more than 2,000 characters → 413 (D35).
  4. The token:
     - a valid one gives its conversation,
     - a missing one is minted, and the `conversations` row is inserted with the first message,
     - an invalid one, or one from another store, → 401 (Review Focus 2).
  5. Mask the message (`maskPII`), save it, and read the last 20 messages, all in one `forStore`. The transaction ends there.
  6. Open the stream and run `rewriteQuery` → `search` → `liveCheck` → `answer`. `product` events are sent as markers resolve; the widget groups them after the text (UD12).
  7. Save the assistant message, then send `done {conversationToken}`. The row holds `content`, `product_ids`, the `cards` snapshot, `model`, the tokens of the rewrite and of every answer call, and `status`.
- **SSE events (§7.6):**
  - `text {delta}`,
  - `product {id, title, imageUrl, url, currency, available, action, stock, price, compareAtPrice, variants[], moreVariants}`,
  - `error {message, conversationToken}`, which carries the token too, so a failed first turn doesn't leave the conversation orphaned,
  - `done {conversationToken}`.

  A `: ping` comment every 15 s keeps proxies from closing an idle stream.

- **C11 = (b)** simple cards from our own copy (picture, name, link), with no price, stock or Add to cart, and the bot says nothing about price or stock.

- **C15 = (b)** history shows the saved card snapshot exactly as the shopper saw it, with no live re-check. The cart still charges Shopify's real price at checkout. `// ponytail:` a reopened card can show a stale price or stock until the shopper asks again.

- **C17** stays conditional: it is raised only if Task 13 Step 3 finds no store language.
- **C18 = (a)** rewrite every message; no skip logic.
- **C19 = (a)** save a cut-off answer with `status = 'cut_off'`.

The options considered are kept below for reference.

- **C11 What a chat answer shows when Shopify can't be reached** (busy, the store's connection expired, or slow):
  - (a) the answer in text only, with no product cards,
  - (b) simple cards from our own copy (picture, name, link) with no price, no stock and no Add to cart, and the bot says nothing about price or stock,
  - (c) "Assistant unavailable right now" and no answer.
  - **Recommended: (b).** The shopper still gets useful suggestions and can click through, and we never show a price or stock we haven't just checked.
- **C12 How many variants (sizes, colours…) a card can offer.** Shopify limits how much one request can ask for, and all of a turn's products share one request.
  - (a) up to 25 per product,
  - (b) up to 50 per product (confirmed by measuring the cost in Task 15),
  - (c) all of them, using a second request for big products.
  - Products with more variants than the limit get "View options", which opens the product page. **Recommended: (b).** It covers almost every real product in one request and stays fast.
- **C13 What the 20-second OpenAI timeout in §8 means:**
  - (a) 20 s to wait for the first word, then up to 60 s for the whole answer,
  - (b) 20 s for the whole answer.
  - **Recommended: (a).** Long answers from the large model can take more than 20 s to finish even when nothing is wrong.
- **C14 Whether the bot sees exact stock counts.** Cards show "Only N left" only below the merchant's threshold (default 5, UD10).
  - (a) the bot sees the same as the card: a count only below the threshold, otherwise "in stock",
  - (b) the bot always sees the exact count.
  - **Recommended: (a).** The bot and the card never disagree, and the bot doesn't reveal large stock numbers the merchant may not want shown.
- **C15 Product cards when the shopper reopens the chat on another page:**
  - (a) check prices and stock again, live (one Shopify request each time the chat is reopened),
  - (b) show the cards exactly as they were (no request, but prices and stock may be out of date),
  - (c) show earlier answers without cards.
  - Either way, the cards are saved, so the dashboard can replay them "as the shopper saw them" (UD22). **Recommended: (a).** A card with Add to cart should never show a stale price.
- **C16 When the storefront doesn't tell us the shopper's country** (D77):
  - (a) skip the country check, and treat the shopper as being in the store's main market,
