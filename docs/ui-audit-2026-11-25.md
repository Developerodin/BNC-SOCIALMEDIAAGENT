# AskCart widget: UI/UX and motion audit

Commit audited: `53c7144` (main). Evidence: code reading, plus Playwright screenshots in `C:\Users\INTEL\askcart-ui-check\shots\audit-desktop`, `shots\audit-phone` and `shots\audit-arc` (the multi-variant "Arc Wall" sheet, with a layout measurement script `C:\Users\INTEL\askcart-ui-check\audit-sheet.mjs`). Build at audit time: widget **22,365 B gzip of 30,720** (about 8.3 KB headroom), launcher **2,633 B of 4,096** (about 1.4 KB headroom).

Skills applied: `ui-ux-pro-max` (priority table: a11y, touch, performance, forms), `impeccable` audit mode (product register, the 5-dimension audit), `improve-animations` (AUDIT.md: 8 categories and its exact curves and durations), `animation-performance` (the property-tier table, "name the cause"), `ui-animation` (easing defaults, "confirm in place", "animate paired states", reduced motion for WAAPI). **`review-animations` could not be loaded**: it is user-invoke only (`disable-model-invocation`). Run `/review-animations` on the builder's diff after the motion chunks land.

## 1. Summary

1. **Bug 3 (cart state lost after "View product") has two causes.** "Added · View cart" exists only in a per-page DOM node. Variant selection never reads the cart, so after a reload the sheet shows "In your cart" next to a blank "Choose Color" and a disabled Add. Fix: a persistent "In your cart · View cart" row, plus pre-selecting the variant that is in the cart (P0).
2. **The sheet photo crop is confirmed and measured.** `aspect-ratio:1` plus `max-height:320px` on a 388px-wide box gives 388×320 with `object-fit:cover`, so tall products (snowboards) lose their top and bottom. On the wide panel it would be 728×320. Fix: a capped square with `object-fit:contain` (P0). I could not reproduce the "flush left" padding: the harness measures 16px. Section 2 lists what to check on the live store, and the fix makes the padding 20px either way.
3. **Cards get their own Add button**, as a sibling of the tile button (a button can't nest inside a button). A single-variant product adds straight from the card. A multi-variant product shows "Choose options" and opens the sheet. The add logic is pulled out once and shared, not copied (P1).
4. **Motion today:** open animations exist but use the built-in `ease-out`. Close is an instant cut, as are the sheet opening and closing, message and card arrival, and the cart badge. The panel also re-animates when it is restored on every page load. Proposed: one motion token set, CSS transitions plus a few WAAPI calls, about 2 KB gzip, with every WAAPI call gated on `matchMedia('(prefers-reduced-motion: reduce)')`, because CSS media queries don't stop WAAPI (P1).
5. **Phone a11y issues:** the variant `<select>` is 13px, so iOS zooms the page on focus (the textarea was already fixed for this). The Add button is 40px tall and the sheet's back button 36px, both under 44px. All proposals fit the budgets: about 4.5–5 KB gzip in total, giving an estimated 27.5 KB of 30. Launcher changes are CSS only, about 60 B.

## 2. Findings

Severity follows impeccable: P0 = blocks the task or the user flagged it as broken, P1 = major or a WCAG/touch failure, P2 = minor or polish.

### P0

**P0-1. Cart state is lost after navigation: View cart disappears, the select resets, Add is disabled while "In your cart" shows** (user complaint 3)
- Where: `widget/src/cards.ts:398-399` (`full` is cached per tile, in page memory only), `:282-290` ("Added · View cart" is written into `status`, a DOM node that is rebuilt empty on the next page), `:154-160` (`selected` starts as `""` per option unless only one value is available; the cart is never consulted), `:198-200` (`watchInCart` only drives the badge text), `:225-228` (no `chosen` gives a disabled button and "Choose Color first").
- Why it happens, step by step: the add succeeds, then "View product" does a same-tab navigation, then the launcher restores the panel (`launcher/launcher.ts:185`, UD13), then history redraws the cards (`messages.ts:95-99` → `renderCards`). Opening the tile builds a **new** `cardEl`: `status` is empty, `selected` is empty, but `cartState()` reads `/cart.js` (`cart.ts:329`), so the badge shows "✓ In your cart". The result contradicts itself: in the cart, nothing chosen, Add disabled.
- Related (from code, not filmed): on desktop the chat comes back as the **floating** panel, not the drawer it was opened in. `uiState` stores only `open/teaserSeen/wide` (`core/storage.ts:44,63-67`), and the restore call passes no `mode` (`launcher.ts:185`).
- Skill: ui-ux-pro-max §8 forms and feedback ("state must survive"); impeccable product register (every component needs its states; a disabled CTA must explain itself and must not contradict the badge); ui-animation "confirm in place".
- Fix:
  1. **Persistent cart row.** Replace the `cartBadge("ac-card__incart")` + `status` pair in the sheet (`cards.ts:193-200`) with one row that is drawn from the cart state on every `CART_CHANGED`: `[✓ icon] In your cart · View cart`, where "View cart" is a `link(cartHref,…)`. Show it whenever `qty > 0`, on store pages only (`watchInCart` already returns early when hosted; the hosted page has no cart read). `status` then carries **errors only**. Success is confirmed on the button itself (P1-4).
  2. **Pre-select from the cart.** Give `watchInCart`'s callback the `CartState`, not only `qty`; one signature change with 2 callers, both in this file. In `addControls`, keep a `touched` flag (set it in the select `change` handler). When the cart state arrives and `!touched && !chosen`, pick the variant of this card with the highest cart quantity that is still `available`, copy its option values into `selected`, set each `selects[i].value`, then `update()`.
  3. **Fallback when nothing is in the cart (needs a user decision).** Option A: pre-select the first available variant. Shopify themes do this (`selected_or_first_available_variant`), so it looks native. Option B: keep "Choose {option}" (the current behaviour). I recommend A **in the sheet only**. Card quick-add never adds a variant the shopper didn't see (P1-1).
  4. Optional: remember the drawer. Add a `drawer` field to `uiState` and pass `mode` in the restore call. This is a storage change in the launcher bundle, about 40 B.
- Failure modes: a cart read that lands after the shopper picked an option must not override it (the `touched` flag). The in-cart variant may now be sold out (skip it, fall back). The hosted page has no cart, so behaviour there is unchanged. Two variants in the cart: take the highest quantity; ties go to the first in `variants` order.
- Size: about +0.3 KB gzip.

**P0-2. The sheet photo is cropped** (coordinator issue 1)
- Where: `cards.ts:463` `.ac-sheet .ac-card__img{aspect-ratio:1;max-height:320px;…;object-fit:cover}` plus `:466` `width:100%`. Measured in the drawer: **388×320, object-fit: cover** (`audit-sheet.mjs` output). The width wins over the aspect ratio, so cover crops the top and bottom. In the wide panel the box would be about 728×320.
- Skill: ui-ux-pro-max §3 (reserve space with a stable aspect ratio) and §4 (match the product type: on e-commerce the product must be fully visible); impeccable "strangeness without purpose".
- Fix: `.ac-sheet .ac-card__img{width:100%;max-width:360px;aspect-ratio:1;max-height:none;margin:0 auto;object-fit:contain;background:#f4f4f4;border-radius:12px;mix-blend-mode:multiply}`.
  - `contain` shows the whole product.
  - `multiply` blends the white backgrounds most Shopify product photos have into the #f4f4f4 box, so there is no white square inside a grey one. It is a static paint cost, not animated.
  - On the wide panel the 360px cap keeps the image square and centred instead of a 728px-wide band.
- Cards (P2, user decision): 168px tiles also use `cover` (`cards.ts:442`), so tall products crop there too. The same `contain` + `multiply` on `.ac-tile__img` would show whole products, at the cost of uneven visual weight across the row.
- Size: about 40 B.

**P0-3. Sheet content flush against the left edge in the store drawer** (coordinator issue 2)
- Where: `cards.ts:460` `.ac-sheet__body{…padding:16px…}`; `:464` `.ac-sheet .ac-card__body{padding:14px 0 0}`.
- Evidence: **not reproduced.** In the harness drawer at 1280×860, `.ac-sheet__body` measures `padding:16px`, the panel x is 860 and the content x is 876.   - (c) The screenshot shows a different surface.
  - Ask for DevTools → Computed `padding` on `.ac-sheet__body` in the shadow root.
- Fix regardless: `.ac-sheet__body{padding:16px 20px 0}`, a sticky action footer (P1-3) with `padding:12px 20px calc(12px + env(safe-area-inset-bottom))`, and `.ac-sheet .ac-card{max-width:440px;margin:0 auto;width:100%}` so the wide panel gets a readable column instead of full-bleed text.
- Size: about 60 B.

**P1-5. Panel and drawer close is an instant cut, and open uses weak built-in easing** (user complaint 4)
- Where: `styles.ts:13` `animation:in .2s ease-out`; `:17` `.panel.drawer{animation:sl .25s ease-out}`; `:21` keyframes; `panel.ts:588-599` `close()` sets `hidden` at once.
- Skill: improve-animations §2 (built-in `ease-out` is too weak; use custom curves), §3 (popovers scale from their trigger); ui-animation "animate paired states together" and "emerge from the trigger".
- Fix:
  - **Floating panel open**: `@keyframes in{from{opacity:0;transform:translateY(8px) scale(.96)}}`, `animation:in .22s cubic-bezier(0.22,1,0.36,1)`, with `transform-origin:bottom right` (`.panel.left{transform-origin:bottom left}`) so it grows out of the launcher.
  - **Drawer open**: `animation:sl .3s cubic-bezier(0.32,0.72,0,1)`.
  - **Phone full screen**: keep the `in` keyframe but without scale: `.panel.full{animation-name:inf}` with `@keyframes inf{from{opacity:0;transform:translateY(16px)}}`, 0.24s, enter curve.
  - **Close (WAAPI)** in `close()`, after the existing state updates:
    1. Set `panel.inert = true`.
    2. `const a = panel.animate(frames, {duration, easing:'cubic-bezier(0.23,1,0.32,1)'})`.
       - Floating: `[{opacity:1,transform:'none'},{opacity:0,transform:'translateY(8px) scale(.97)'}]`, 160ms.
       - Drawer: `[{transform:'none'},{transform:'translateX(100%)'}]`, 220ms.
       - Full: opacity plus `translateY(16px)`, 180ms.
    3. `a.finished.then(()=>{panel.hidden=true;panel.inert=false}, ()=>{})`.
    4. Focus restore and `ui.open.set(false)` happen **immediately**, not after the animation.
    5. `open()` must `panel.getAnimations().forEach(x=>x.cancel())` and clear `inert` before showing, so a reopen during the exit works.
    6. When reduced motion is on, skip the animation and hide at once.
  - `destroy()` stays instant.
- Failure modes: rapid open/close (handled by cancel); `close()` during a turn (unaffected). `lockScroll(false)` should run immediately, as now.
- Size: about 0.3 KB gzip.
